# 澄初 · 商品智能导购助手 v2（FDE 08 题）

> 字节 FDE 实习生考试第 08 题 · 独立原型 · 飞书商业化方向
> 内核：**LLM 只做翻译、代码做决策**（信任主线：客需匹配 × 预算匹配 × 信任，绝不替顾客做主、绝不编造）

本包在**无网络 / 无 API key** 时也能完整运行（自动离线兜底），方便面试现场稳定演示。

---

## 一、这是什么题

给一个虚构品牌「澄初个人护理」做一个**商品智能导购助手**：帮顾客从「先了解需求 → 给选择」，
同时要守住 10 条可检查行为（BC-1~10，见 `tests/test_bc.py`）。

关键约束（品牌手册未提供 → 一律「需要向门店或系统确认」，不得编造）：
- 促销 / 折扣 / 赠品 / 领券
- 线上渠道价格 / 保价 / 比价
- 退换货政策
- 渠道授权 / 代理 / 会员

## 二、为什么是「LLM 翻译 + 代码决策」

这是本方案的**唯一差异化亮点**，也是面试最容易被追问的点：

| 决策事项 | 归谁 | 为什么 |
|---|---|---|
| 推荐哪个 SKU、组合价多少 | **代码**（`rules.py` 确定性规则） | 价格算术、安全边界必须可复算、可单测 |
| 是否合规、是否要升级/拒绝 | **代码**（门控 + 优先级路由） | 政策/敏感/医疗/注入属永不翻车的红线，不能交给概率 |
| 读不懂用户话里槽位 | **LLM 意图抽取**（`nl.extract_intent`） | 用自然语言抽槽，补足关键词漏判 |
| 把「决策结果」说得自然 | **LLM 措辞**（`nl.word_reply` / `polish_reply`） | 只润色语气，**不改决策事实** |

核心承诺：
1. **价格白名单**：任何外发金额必须 = 事实表价格，或 = 若干事实价格之和（子集和校验）。违规一律丢回硬模板。
2. **红线不走 LLM**：注入 / 敏感 / 医疗 / 政策 / P201 前置，永远由确定性模板输出。
3. **离线可跑**：无 key 时 key 相关调用全部跳过，模板照常输出。

## 三、目录结构

```
FDE08_商品智能导购_v2/
├─ brand_kb.py         # ★单一事实源：品牌定位 / 6个SKU / 2个组合 / 白名单价 / 政策 / 追问原则
├─ rules.py            # ★确定性规则层：detect→route→decide→render(硬模板)
├─ nl.py               #    LLM 翻译层：意图抽取 + 措辞 + 价格白名单校验（可离线）
├─ agent.py            #    编排层：缝合 规则决策 与 LLM 翻译；chat()/trace()/sanity_ping()
├─ server.py           #    FastAPI 入口：静态页 / api/health / api/trace / api/chat
├─ requirements.txt    # fastapi / uvicorn / httpx
├─ start_demo.bat      # 一键：起 uvicorn + cloudflared 临时公网隧道
├─ .env.example        # 复制为 .env 填 key（没有 key 也能跑）
├─ static/index.html   # 前端聊天 + 「决策透视」面板
├─ tests/
│  ├─ test_scenarios.py # 离线 16 场景全绿
│  └─ test_bc.py        # BC-1~10 验收全绿
└─ *.md                # 交付说明 / 演示脚本 / STAR复盘 / 面试官问答
```

## 四、运行 & 演示

**方式 A：只跑确定性内核（面试最稳，无网络依赖）**
```bash
cd FDE08_商品智能导购_v2
python tests/test_scenarios.py   # 16 场景
python tests/test_bc.py          # BC-1~10
```

**方式 B：起 Web 演示**
```bash
# 1) 安装依赖
pip install -r requirements.txt
# 2) （可选）填 key：把 .env.example 复制为 .env 并填 DEEPSEEK_API_KEY
# 3) 一键起服务（uvicorn + cloudflared 公网隧道）
双击 start_demo.bat         # 或 python -m uvicorn server:app --port 8000
```
浏览器打开 `http://127.0.0.1:8000`，右侧「决策透视」可实时看规则层如何路由。

## 五、验证

- **离线 16 场景**：`tests/test_scenarios.py` —— 覆盖正常/澄清/敏感/政策/医疗/P201两段/注入/明确SKU/旅行/超预算/无P301泄漏/追问≤2。
- **BC-1~10**：`tests/test_bc.py` —— 题库 10 条可检查行为，含**子集和价格校验**（388=P101+P203 这类非手动组合也能复算）。
- **HTTP**：`/api/health`、`/api/trace`、`/api/chat`、`/`(index) 全部连通。

## 六、安全 & 边界（重要）

- 手册未提供的信息**一律不编造**（价格/促销/退换/授权），统一「需要向门店或系统确认」。
- 8% 果酸 P201 是**敏感边界核心**：敏感/没经验 → 直接拒绝并温和建议；稳定+有经验 → 先询问再推荐。
- 旅行分装 P301「自带分装」才推荐；**非旅行场景不得出现 P301 / 便携 / 分装等词**。
- 注入/越狱、医疗功效、急性不适 → 硬模板兜底，绝不外发未校验文本。
- 所有**外发金额**都过 `nl.validate_prices`（事实价 ∪ 子集和），否则回退模板。

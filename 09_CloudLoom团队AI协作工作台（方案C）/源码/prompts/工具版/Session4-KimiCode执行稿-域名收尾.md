# Session 4 · 域名 HTTPS 收尾批（备案通过后执行）—— Kimi Code 执行稿

> **运行方式**：SSH 登录服务器 → `cd /opt/team-console && kimi --yolo -m kimi-code/k3-256k` → 粘贴**本稿全文**。
> **触发条件**：① 腾讯云控制台显示域名**已备案**；② `nslookup <域名>` 返回 `<服务器IP>`。
> 本稿为**一次性完整执行**设计，用于把 Session 0/3 中标记「延期补做」的域名相关项全部收口。

---

## 0. 开工前置（必须先做，任一不满足则报告并停止）

```bash
nslookup <域名>            # 必须返回 <服务器IP>
curl -sI http://<域名> | head -3    # 备案通过后应能正常回应（此前会被拦）
```

- 并确认：腾讯云**安全组已放行 80/443**（B2 依赖项之一）；若需 DNS-01（DNSPod 凭据）：凭据只写入 Caddy 环境文件/`.env`，**不上屏、不进报告原文**
- 读取 `/opt/team-console/SPEC.md`（重点：五、第 6 阶段；五、第 9 阶段第 7 项与 PWA 相关内容）
- 读取 `/opt/team-console/reports/Session3-部署报告.md`（找到所有标「延期补做」的条目）
- 若 `nslookup` 未指向本机 → **停止**，报告管理员检查 DNSPod 的 A 记录（@ / www）

## 1. 目标

1. **正式证书签发**：Caddy 为 `<域名>` 与 `www.<域名>` 签发有效证书
   - 首选 HTTP-01（Caddy 自动）；若 80 端口验证被拦，改用 **DNS-01（DNSPod 插件，需在 Caddyfile 配 DNS provider 凭据）**
2. **HTTPS 全链路验收**：`https://<域名>` 返回工作台页面（非 Caddy 默认页/超时），证书链有效、无浏览器告警
3. **PWA 全链路复跑**：Service Worker 注册成功、`manifest.json` 可访问、手机「添加到主屏幕」、**通知弹窗实测**
4. **复跑延后项**：Session 3 的 19 项验收中因域名延后的项目（至少第 7 项；如第 5/8/16 项与域名相关的部分一并复核）
5. **备案合规收尾**：页面底部按要求标注备案号（格式：`苏ICP备xxxxxxxx号`，链接到 `https://beian.miit.gov.cn`）；若备案号尚未下发，记录待办
6. **更新部署报告**：在 `reports/Session3-部署报告.md` 追加「HTTPS 收尾」章节

## 2. 常见故障排查（本批高发）

| 症状 | 排查方向 |
|---|---|
| 443 连接被重置/返回未备案页 | 备案是否**已通过并同步**（管局通过后有同步延迟）；确认域名与备案主体一致 |
| 证书签发失败（HTTP-01） | 80 端口是否被拦；改用 DNS-01（DNSPod API 凭据） |
| `nslookup` 不对 | DNSPod A 记录（@ / www 都要）；TTL 等待 |
| 手机通知不弹 | iOS 需先「添加到主屏幕」再授权；确认 HTTPS 有效（PWA 硬要求） |
| 证书有效但页面 502 | 后端 8787 未启动 / 前端未 build；`systemctl status` 逐个查 |

## 3. 验收（本批全部通过 = 项目域名侧闭环）

1. `https://<域名>` 与 `https://www.<域名>` 均正常访问（证书有效）
2. PWA：可添加到主屏幕；通知实测弹出
3. Session 3 报告中的「延期补做」条目**全部关闭**（逐条标注通过）
4. 备案号已标注在页面底部（或记录明确的待办与预计时间）
5. 更新后的 `reports/Session3-部署报告.md` 中「延后项」章节变为「全部关闭」

## 4. 约束（本批铁律）

- 不改动已验收代码（除 Caddy 配置、证书配置与报告更新）
- 凭据（DNSPod 等）只进 `.env` / Caddy 环境文件；报告脱敏
- 遵循 SPEC 约束 B2 / D13：对外访问方式 = **域名 + HTTPS**（不以 IP 直连对外）

## 5. 结束动作

输出：证书状态、域名验收结论、延后项关闭清单、报告更新位置。然后**停止**。

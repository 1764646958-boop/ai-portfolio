5. **MCP 网关收尾（v3.1）**：确认 `/mcp` 端点经 Caddy 可达；验证 4.11.2 接入能力

   外部 MCP（TencentDB/MySQL 等）"的配置说明文档
6. 全量端到端验收（SPEC 第 9 阶段 **19 项**，逐项执行并记录）

## 执行要求
1. 每个 Tab 完成后浏览器实测（登录态、权限、交互）
2. 手机浏览器实测响应式（或至少 DevTools 设备模拟）
3. **19 项验收逐项执行并记录结果**，不允许只做"代码 review"代替实测
4. 验收失败项必须修复后重测，直到通过
5. PWA 通知实测：允许通知后触发一次测试通知
6. **第 6 阶段部署前先确认 ICP 备案已通过**（腾讯云控制台查"已备案"）；若未就绪：暂停**对外 HTTPS 部署与验收**（SPEC 约束 B2：不得以 IP 直连对外代替；`npm run build` 与 Caddy 路由可先行就位、仅本机自检）；域名/证书/PWA 项标记「延期补做」（Session 4 备案通过后收口），其余前端工作与验收照常继续

## 本批验收标准（SPEC 第 9 阶段全部 19 项，v3.2）
1. 4 个成员账号：首个管理员、后续需批准、会话互不串
2. 聊天流式正常；4 预设 Agent 行为不同记忆独立；DeepSeek key 真实
3. 看板 Tab 任务可见；新建任务→值班Agent 执行→刷新出现
4. 画像 Tab：普通成员只见自己，管理员全见
5. 私聊+群聊准实时、未读红点；@Agent 答完即走；撤回生效；刷新历史不丢
6. 资料库：≤10MB 上传、网盘链接、同列表
7. HTTPS 证书有效（**前置：域名 ICP 备案已通过**）；手机添加到主屏幕；PWA 通知弹窗实测
8. reboot 后全部服务自动恢复；自动快照已开启
9. cron 到点：晨报写文件+邮件；画像 JSON 生成
10. 懒启动全流程（唤醒→60s→30min 停止→再次拉起）
11. 办公任务中心全流程（含排队、失败场景）
12. N4 结论记录在部署报告（方案 A 或 B，且 @Agent 按结论实现）
13. 记忆库：自动沉淀、FTS 检索、ACL 三态、手动新建
14. 融合闭环端到端（任务1→记忆→任务2引用→生效）
15. Skill 链路：hermes skills list 可见、提问触发生效
16. **MCP 网关（v3.1）**：外部 MCP 客户端经 Caddy 可达 `/mcp`，`memory_search` 按成员 token 检索可见记忆（ACL 生效）、`task_create` 创建任务出现在工作台
17. **入口唯一（v3.1）**：全程无 WorkBuddy/外部办公工作台依赖；成员仅通过工作台完成全部操作；模型切换在配置层完成
18. **修正反馈闭环（D35，v3.2）**：requires_approval 任务 → waiting_approval → 审批"修改"+理由 → task_corrections 落库 → 同类任务注入【相关修正记录】生效
19. **行为边界与升级规则（D34/D36，v3.2）**：四 Agent SOUL.md 均含「行为边界」小节 + HERMES.md 边界总表；"删除文件/对外承诺/报预算"指令自动 requires_approval；不可能任务 Agent 明确"无法完成+原因"

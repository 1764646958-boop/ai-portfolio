## 1. 山河云台主题（D6）

- **现状**：素净极简界面已上线（Tailwind，含深浅色），满足「先能用」。
- **为什么现在不做**：主题属观感层，优先级低于机制跑通；提前做会牵动全部视图返工。
- **二期做法**：把「山河云台」主题设定包作为素材接入，只动样式层（配色/字体/组件皮肤），**不动任何接口**。
- **触发条件**：机制稳定、成员对现有观感提出明确诉求时。

## 2. 群聊 Agent 常驻开关

- **现状**：`@Agent` 为**拉入答完即走**——Agent 临时参与该轮对话，回复后不常驻会话成员列表。
- **为什么现在不做**：常驻会持续消耗上下文与 token，4 人团队的协作尚未证明需要。
- **二期做法**：增加「常驻开关」，可把指定 Agent 固定为群成员。
- **触发条件**：某 Agent 需要持续跟踪同一话题（如长期值班）时。

## 3. 记忆库升级为向量语义检索（D31 + SPEC 七）

- **现状**：自研 SQLite 记忆库（`data/team-memory.db`）+ FTS5 关键词检索（trigram），**不依赖 TencentDB**。
- **为什么现在不做**：4 人团队每天几十条记忆，显式沉淀（任务结论 + 手动保存 + cron 画像）已覆盖约 90% 协作记忆；2 核 4G 资源紧张，加 TencentDB 三件套大概率 OOM；记忆抽取持续烧 token（几十～几百元/月）。
- **切换触发条件（满足任一即评估切换）**：
  1. 「群里随口定的决策经常找不到」→ 需要对话自动捕获（L0-L4 分层）
  2. 「搜文件只能靠文件名，搜不到内容」→ 需要 Wiki / CodeGraph 语义检索
  3. 游戏开发启动，TencentDB 反正要部署给游戏用 → 一套基础设施两用，边际成本最低
- **切换成本与方式**：记忆层已隔离在 `/api/memories` 接口之后，**前端、任务中心、闭环一行不改**；只重写代理层记忆 API 后端（对接 TencentDB SDK / MCP），约 1-2 天。对话记忆走 Hermes 官方 `memory_tencentdb` provider，文件记忆走 MemoryKnowledge 知识服务（8424）。
- **v3.1 补充（MCP 方式）**：TencentDB 也可作为外部 MCP server 接入（`hermes mcp add`，见 SPEC 4.11.2）——接入后其记忆工具自动进入 Agent 工具集，可与自研记忆库**并存过渡**，切换更平滑，前端无感知。
- **决策记录**：2026-08-18 团队确认——现在自研跑通机制，游戏开发期部署 TencentDB，团队记忆层按触发条件切换。

## 4. 可观测：统计级（D32）

- **现状**：无统计面板；可观测依赖 systemd/journalctl 日志 + 任务表本身。
- **为什么现在不做**：统计级看板需要先有稳定的调用日志与任务量基数，属于「有数据后再看」的能力。
- **二期做法（统计级，明确不做 Trace）**：
  - 每 Agent：调用次数 / 成功率 / 平均耗时 / Token 估算
  - 成本看板（DeepSeek 按量估算）
  - 高频场景 TopN、低成功率链路提示
- **数据源**：任务中心 + `/api/chat` 日志 + cron 画像。

## 5. 记忆评测集与工程纪律闭环

- **二期做法**：为 4 个预设 Agent 各建立 20-50 条黄金用例，形成记忆检索效果的回归评测。
- **D35 数据一并纳入**：修正反馈闭环产生的 `task_corrections`（阶段 3 已落库并有真实记录）随记忆评测集一起纳入，用于衡量「修正是否真的减少了重复被否」。

## 6. 运营统计：修正率指标

- **定义**：修正率 = 被打回任务占比（`waiting_approval` 中审批人选择「修改」的比例）。
- **用途**：作为 Agent 质量指标，配合评测集观察机制改进是否见效。

## 7. 「初见报告」机制（借鉴 Memmy）

- **二期做法**：新成员或新 Agent 加入时，自动生成「团队初见报告」（团队现状 / 关键决策 / 协作习惯），降低冷启动成本。
- **依赖**：团队记忆库中的 decision 类记忆（阶段 3 已具备，手动新建 decision 记忆已验证可检索）。

## 8. 边界决策：不做 Agent 治理平台（D33）

- **决策**：不做「跨平台智能体纳管 / 调度 / 治理平台」——那是 ADP Agent Portal 的主场（巨头赛道）。
- **定位**：方案 C = **小型创意团队的数字员工办公室 + 团队记忆容器**。
- **对二期的约束**：二期功能不得把项目带向「治理平台」形态；新增能力必须服务「4-10 人创意团队协作」这一场景。

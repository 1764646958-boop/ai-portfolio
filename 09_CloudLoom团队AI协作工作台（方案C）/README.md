# CloudLoom · 团队 AI 协作工作台（原「方案C」）

> **让 3 人异地工作室拥有一位"数字员工办公室"：一个页面完成协作、任务、记忆与执行，并把每一次协作沉淀成可复用的团队记忆。**

## 1. 业务问题

3 人异地工作室（策划 / 程序 / 评审 / 值班四类角色），日常协作散落在群聊、网盘与个人笔记里，三个具体痛点：

1. **AI 用得散**：每次都要重新交代背景，产出无法沉淀，下次还得从头讲；
2. **任务执行没有容器**：谁在做什么、卡在哪、产出在哪，靠人记；
3. **团队记忆留不住**：群里随口定的决策，过几天找不到。

目标不是"再买一个 SaaS"，而是回答一个问题：**一个小团队能不能自建一个"数字员工办公室 + 团队记忆容器"，且入口唯一、零件可换？**

## 2. 为什么用 AI，以及边界在哪

- 办公任务（汇总 / 起草 / 分析 / 复核）本身就是 LLM 的强项，值得做成一等公民；
- 但"自由发挥"会带来风险，所以确立**分工第一性原理**：
  - **语义归模型**（写、译、汇总、建议）
  - **确定性归规则**（权限、状态机、审批、计费口径）
  - **不可逆决策归人**（涉金额 / 对外承诺 / 删除数据三类任务强制人工确认）
- **边界决策**：不做通用 Agent 治理平台（巨头赛道），只做"小团队的数字员工办公室 + 记忆容器"。

## 3. 架构与护栏

```
成员 ──► 单页工作台（7 个 Tab：聊天 / 看板 / 任务 / 画像 / 资料库 / 记忆 / 设置）   ← 唯一入口
                      │
                      ▼
            自研代理层 :8787（同时是 MCP 网关 /mcp）
              ├─ 任务中心：状态机 queued→running→waiting_approval→done/failed
              ├─ 团队记忆库：SQLite + FTS5，可见性 private / team / restricted
              ├─ 资料库：≤10MB 直传，超限走网盘链接
              └─ 会话：私聊 + 群聊 + @Agent 拉入（成员互聊不调用模型，零成本）
                      │
                      ▼
       4 个常驻 Agent（仅绑 127.0.0.1）+ 自建 Agent 懒启动（端口池 8650-8999）
                      │
                      ▼
         Caddy（HTTPS / PWA）· systemd（UMask=0077 + 最小沙箱 + 启动限流）
```

**四道护栏**
1. **入口唯一 / 零件可换**：成员只面对工作台；模型、存储、外部平台都可在配置层替换；
2. **行为边界三清单**（每个 Agent 的 SOUL.md 显式定义：可自主 / 需升级人审 / 禁止 + 失败兜底），并汇总为团队可查的边界总表；
3. **强制人审 + 反馈闭环**：三类高风险任务自动进 `waiting_approval`；审批的"通过 / 打回 / 修改"落库为修正记录，下次同类任务自动注入 —— **"成员改了什么，Agent 记住"**；
4. **融合闭环**：任务完成 → 产物落 `产出/<task_id>/`（附 `MANIFEST.json` 校验清单）→ 自动沉淀结论记忆 → 下次任务可检索引用。

## 4. 评测与复盘

| 层次 | 做法 | 结果 |
|---|---|---|
| 功能验收 | 19 项端到端（含 reboot 恢复、懒启动全周期、PWA 通知、权限边界） | 17 项通过；2 项环境性延期并显式标注（不使用"已知问题"蒙混） |
| 界面回归 | `e2e3.mjs` 真实浏览器 42 项断言 | 每批次后复跑，终态 42 PASS / 0 FAIL |
| 缺陷管理 | 分级编号 C-1…C-14，逐项修复或标注剩余风险 | 高危 4 项（C-1/C-2/C-13/C-14）修复包专批交付 |
| 独立复核 | 助手侧 **5 轮**"不上自述、直接实测"复核 | 每轮留档复核记录；含亲手复现（见 §5） |

**几个"只有真跑才会发现"的坑（复盘节选）**

- `app.listen` 的回调在 **Express 5** 下会被同时注册为 error 监听 → 端口占用时回调照常触发、第二实例仍会误判孤儿任务重排（用 **err 感知回调 + 就绪闸门**修复）；
- **FTS5 外部内容表不随主表级联删除** → 清空记忆后搜索仍能搜出已删内容（补探针验证才暴露）；
- 删除 Agent 时 **systemd drop-in 残留**（`gateway uninstall` 不清理）→ 显式清理，复测 1→0；
- 定时作业因 API 余额见底连续失败却**完全静默**（`deliver=local`）→ 催生**运维看门狗**：15 分钟一次、不依赖 LLM、只在异常时写通知并发出站邮件。

## 5. 指标（均为实测）

**成本治理（负责人自费 API，故按成本做了专项）**

| 维度 | 改动前 | 改动后 |
|---|---|---|
| 定时 LLM 作业 | 15 次/周（每日晨报 + 每日画像 + 每周复盘） | **1 次/周**（周报含复盘）+ 1 次/天 **0-token 脚本快照** |
| 预计花费 | ≈¥1.24/周 | **≈¥0.069/周**（−94.5%） |

- 一次周报实测 **$0.00953 ≈ ¥0.069**（14 次调用 / 输入 42,662 / 输出 7,537 / 缓存读 516,864 tokens）；
- 新增**用量台账**（每次 Agent 调用落库 tokens + 估算花费），周报里带"本周花费 + 按 Agent/成员分布 Top5"；
- **长会话上下文瘦身**：无状态 API 默认只带最近 12 轮（可配），避免每轮重发全部历史。

**懒启动（2C4G 小机，4 个常驻 + N 个按需）**

- 唤醒：waking 0.2s / ready 4.3–4.5s / 首字 8.5–11.4s；
- 空闲自动停机：实测 30min 1s、30min 2s 触发，`ExecMainStatus=0`、端口即时释放。

**可靠性加固（S4.0 八批）**

- 运维看门狗（systemd timer，15 分钟，零 LLM）→ 覆盖：定时作业失败 / 余额阈值 / 单元状态 / 端口 / 健康检查 / 磁盘；
- 最小沙箱（5 条指令）、`systemd-oomd`、启动限流（300s/10 次）、Caddy 日志轮转；
- 登录安全：响应体不再回传 token、Cookie `HttpOnly+Secure+SameSite`、**token_version 登出即全端失效**；
- 前端：SPA 回退收窄（`/api/*` 缺失返回 404 JSON）、通知已读基线、会话记忆按用户隔离。

**独立复核中我亲手复现的四件事（不采信自述）**

1. 第二实例启动闸门（EADDRINUSE ×2、无任务重排、退出码 0、主实例零扰动）；
2. 懒启动 30 分钟准点停机（预测 16:20:42 → 实测 16:20:44）；
3. **看门狗实弹演练**：制造异常 → 告警文件落地 → 工作台 `/api/poll` 真读到 → 静默复核 → 清理痕迹；
4. **0-token 快照**与**用量记账**：跑前后账目计数一致 / 一次真实对话后账目行如约出现。

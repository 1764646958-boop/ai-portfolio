长会话把全部历史都塞进 prompt → 输入 token 随轮数线性上涨，长会话成本失控（且大量是重复的旧内容）。

### 3.2 改动
| 位置 | 内容 |
|---|---|
| `server/src/config.js:67–71` | 新增 `CHAT_HISTORY_MAX_ROUNDS`（默认 **12**，一轮≈user+assistant；设为 0/负数=关闭裁剪，仅供实测对照）、`CHAT_SUMMARY_ENABLED`（默认 **false**） |
| `server/src/context.js` | 默认只保留最近 N 轮，并**补一条系统说明「更早对话已省略」**（不静默丢） |
| 可选摘要路径 | `C.CHAT_SUMMARY_ENABLED=1` 时，被裁掉的早期部分由本 Agent 生成**一次**摘要并缓存复用（默认关：摘要本身也要花 token） |

**不动的东西（明确保留）**：任务上下文注入（`【任务上下文】`）、D35 修正记录注入、`@Agent` 片段注入 —— 均在裁剪之前完成，裁剪只作用于"历史对话轮次"。

- **缓存复用**：裁剪后前缀稳定，上游缓存命中正常（`cache_read_tokens` 非 0）。
- **默认关的摘要路径**：显式开启后实测可用（生成一次摘要并落 `context_summaries`），验证后**已恢复默认关**并删除测试缓存行（剩余 0）。

- **文档**：策略写入 `docs/SPEC-v3.3-微修订草案-20260914.md`（修订 7）与《故障排查表》**§10.5「长会话被裁剪（C3 上下文窗口）」**。

### 3.4 剩余风险
1. 裁剪是**硬截断**（+ 一行省略说明），不做语义摘要；若用户的关键约定落在 12 轮之前且未进任务上下文，Agent 会看不到 —— 缓解方式是页面上的省略提示 + 必要时"共享完整会话"。

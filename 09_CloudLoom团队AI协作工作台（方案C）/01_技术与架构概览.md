# 01 · 技术与架构概览

> 完整规格为 36 条决策清单（v3.2，经 5 轮修订；S4.0 换版 v3.3 对齐现实）。本文件是面向作品集的技术摘要。

## 一、范围（做什么 / 不做什么）

**做**：团队协作层 + 团队记忆层 + 办公执行层 —— 成员在一个页面里聊天、派活、看板、查记忆、取产物。

**不做**（显式边界）：
- ❌ 不做通用「跨平台 Agent 治理/调度平台」（巨头赛道）→ 定位收敛为"小型创意团队的数字员工办公室 + 团队记忆容器"；
- ❌ 不引入外部办公工作台（办公能力由 Agent 工具 + Skill 实现）；
- ❌ 不做游戏运行时记忆（属另一套独立后端，不为它预留接口）；
- ❌ 成员之间聊天**不调用模型**（零 token 成本）。

## 四、关键机制

1. **懒启动**：Agent 不在常驻名单时按需拉起；`ensureRunning` 唤醒 + 已运行实例回写 `lastActive` + 空闲 30 分钟清扫；就绪判定以"是否真正持有 API 端口"为闸门。
2. **任务状态机**：`queued → running → waiting_approval → done / failed`；三类高风险（涉金额 / 对外承诺 / 删除数据）**强制人审**。
3. **反馈闭环（双向学习）**：审批动作落 `task_corrections` → 下次同类任务（同 Agent + 标签）自动注入"上次被否的点"。
4. **融合闭环**：任务完成 → 产物写 `产出/<task_id>/`（含 `MANIFEST.json` 文件名 + sha256 校验）→ 自动沉淀结论记忆 → 下次任务可检索引用。
5. **行为边界**：每个 Agent 的 `SOUL.md` 显式写"可自主 / 需升级人审 / 禁止"三清单 + 失败兜底；团队侧有边界总表。
6. **重启恢复语义**：服务重启把在途任务重新排队，但**标注**「系统重启后恢复（可能与中断前重复执行）」+ 写系统通知 + 产物**不覆盖**（重跑产物另存 `-retry-<时间>` 后缀）。
7. **余额/成本治理**：每次 Agent 调用落 `usage_log`（tokens + 估算花费）；余额低于阈值由看门狗告警。

## 五、安全与运维

| 项 | 做法 |
|---|---|
| 认证 | scrypt 口令哈希；JWT 走 `HttpOnly + Secure + SameSite=Lax` Cookie；响应体不返回 token；`token_version` 实现**登出即全端失效** |
| 权限 | 管理员（Agent 管理 / 成员批准 / 资料库删除）vs 成员（发起任务、对话、记忆）；会话非成员访问 403；停用账号 401 |
| 进程 | 服务以最小沙箱运行（`NoNewPrivileges` / `PrivateTmp` / `ProtectSystem=full` / `ProtectHome=read-only` + 白名单可写路径）；启动限流 300s/10 次 |
| 密钥 | 只存 `.env`（600）；7 处副本 + **一键轮换脚本** + `密钥台账.md`（位置 / 指纹 / 周期 / 负责人） |
| 备份 | 云快照（控制台）+ 每次改动前 `.bak`（本轮 74 份）+ 清理前全量备份 + 回滚脚本（含隔离副本演练） |
| 可观测 | 看门狗 15 分钟体检 → 异常写工作台通知 + 出站邮件（无异常静默）；用量台账支撑成本可见 |

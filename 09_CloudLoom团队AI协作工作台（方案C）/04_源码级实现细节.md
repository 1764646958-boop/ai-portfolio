## 三、任务中心 `tasks.js`（653 行，全项目最大模块）

### 3.1 状态机（`tasks.js:22`）

```sql
status TEXT NOT NULL DEFAULT 'queued',   -- queued|running|waiting_approval|done|failed
approval_status TEXT,                    -- pending|approved|rejected|modified
```

`const STATUSES = ['queued','running','waiting_approval','done','failed']`（`tasks.js:72`）

**队列单飞**：`pump(agentId)` 用进程内 `running` Set 保证**同一个 Agent 不并发执行**（`tasks.js:349,420`）；`queueAhead()` 给前端返回"我前面还有几个"。

### 3.2 三类敏感内容强制人审 —— 是**规则**，不是 Prompt

这是"不可逆决策归人"原则的**代码实体**（`tasks.js:76-101`）：

```js
const APPROVAL_RULES = [
  { kind: '金额',     words: ['金额','预算','报价','费用','成本','定价','价格','付款','支付','发票','万元','合同额'] },
  { kind: '对外承诺', words: ['对外','承诺','合同','签约','客户','甲方','乙方','发布','公告','公开','上线通知'] },
  { kind: '删除数据', words: ['删除','清除','销毁','清空','卸载','覆盖','drop','delete','truncate'] },
];
// 词例外：出现这些完整词时，其中的命中词不算数（如「客户端」不应因「客户」触发对外承诺）
const WORD_EXCEPTIONS = { '客户': ['客户端'] };
```

判定覆盖三类输入：**任务描述 + 引用资料名 + 引用记忆标题**。命中即 `requires_approval=1`，任务停在 `waiting_approval`。

> **为什么用关键词而不是让模型判断**：Prompt 层"请谨慎判断"是不可靠的，模型可以被绕过；关键词规则是**确定性的、可回归测试的**。这是刻意把安全判定放在**代码层**而非**语义层**。

### 3.3 反馈闭环：审批修正回注下一次任务（`tasks.js:184-207`）

```js
// D35：同 agent 近 30 天最近的审批修正记录（最多 5 条）
function buildCorrections(agentId) {
  const since = new Date(Date.now() - 30 * 86400000).toISOString();
  return db.prepare("SELECT * FROM task_corrections WHERE agent_id = ? AND created_at > ? ORDER BY created_at DESC LIMIT 5")
    .all(agentId, since).reverse();
}
```

构建任务指令时，把修正记录拼成 `【相关修正记录】`（含 `[approve|reject|modify]` + 说明 + 决策人 + 日期）一并注入——**"成员改了什么，Agent 记住"** 在代码里就是这 8 行。

三张表分工：`tasks`（任务与状态）/ `task_corrections`（修正记录）/ `outputs`（产物索引）。

### 3.4 交付诚实性协议（★ 本项目最值得讲的一段）

**不是"期望模型诚实"，而是"用协议强制模型表态"**。每条任务指令末尾写死（`tasks.js:216-225`）：

```
5. 回复的最后一行必须是交付状态标记，三选一，格式严格如下（不要加引号、不要改写原文）：
   【交付状态】完成
   【交付状态】无法完成：<一句原因>
   【交付状态】低置信：<一句存疑说明>
```

**解析侧还处理了两个真实陷阱**（`tasks.js:282-306`）：

```js
const RE_NEGATED = /不写|不说|不会说|不会|不用|不标注|不做|不提|避免|并非|不是|不属于|而非|不能称/;
const RE_STATUS = /【交付状态】\s*(完成|无法完成|低置信)\s*[：:]?\s*([^\n]*)/g;
// 首选解析标记（取最后一次出现：Agent 可能引用原文或自我否定，
// 例如「我不写『无法完成』」，纯关键词匹配会被这类句子误导）
```

| 陷阱 | 处理 |
|---|---|
| Agent 在正文里**引用了这句话本身**，或写了自我否定句（"我不写『无法完成』"） | ①**取最后一次出现**；②`RE_NEGATED` 否定语境过滤；③标记优先于关键词启发式 |
| 上游没给标记，只能靠关键词猜 | 降级到 `RE_UNABLE` / `RE_LOWCONF` 启发式，并在返回值里标 `source: 'marker' \| 'heuristic'`——**区分"确定"与"猜的"** |

> **为什么值钱**：它把"AI 说自己不确定"这件事变成了**可被程序消费的结构化信号**，而不是一句人话。这是整条自动化的前提。

### 3.5 独立复核：执行者 ≠ 复核者（`tasks.js:311-325`）

当 Agent 声明不确定时，调**值班 Agent（`zhiban`）**做独立裁决：

```
你是值班复核 Agent（zhiban）。同事 Agent 对自己交付的任务给出了不确定声明，
请判断该任务是否已可交付。
只输出一行 JSON：{"verdict":"pass","reason":"一句理由"}（verdict 只能是 pass 或 reject）
```

**角色分离是设计出来的**（`registry.js:8-13`）：

| 角色 | 定位 |
|---|---|
| `cehua` 策划 Agent | 世界观、剧情、数值 |
| `chengxu` 程序 Agent | 架构设计、代码实现、技术评审 |
| `pingshen` 评审 Agent | **独立只读审查（只评判不动手）** |
| `zhiban` 值班 Agent | 晨报、周复盘、阻塞提醒、催办、**复核兜底** |

> `pingshen` 的定义里"**只读 / 只评判不动手**"是关键——**复核者没有写权限**，这是权限层面而非口头层面的责任分离。

### 3.6 产物清单 `MANIFEST.json`（`tasks.js:227-255`）

产物落 `产出/<task_id>/`，同时写入清单：

```
{ task_id, generated_at, algorithm: 'sha256',
  files: [ { 文件名, sha256, size, mtime }, ... ] }
```

注释里写明用途：**"'不覆盖'的字节级兜底"**——不只记录"有哪些文件"，而是记录"**每个文件的字节指纹**"。清单本身不登记为产物；写入走 `.tmp` + `rename` 原子替换。

### 3.7 重启恢复与重试语义（`tasks.js:438-499`）

| 场景 | 机制 |
|---|---|
| 进程崩溃/重启遗留的 `running` 任务 | **孤儿判定 = DB 标 `running` 但不在本进程的 `running` Set 里** → 立即回收重排，不等超时阈值 |
| boot 时 | 用 **30s 短宽限**回收上一进程遗留（本进程刚起，不可能有在跑的任务） |
| 周期巡检 | **60s 一轮**（`startSweeper`） |
| 重试任务 | 指令里注入 `【重试约束】`：列出中断前已有产物 → **"严禁覆盖或删除上述任何文件"** → 同名必须另存 **`<原名>-retry-<HHMMSS>`** |

> **重申**：恢复语义是"**标注 + 不覆盖 + 清单校验**"，**没有做任务级幂等**——这是如实记录的剩余风险（见 §十一）。

## 四、团队记忆库 `memories.js`（262 行）

### 4.1 检索：FTS5 + `trigram`，并把局限写进注释

```js
// FTS5 虚拟表（D24：中文用 trigram）。⚠️ trigram 只能索引 ≥3 字符的片段，
// 因此 1-2 字的中文查询（如「数值」）在 FTS 上必然 0 命中 —— 由 searchMemories 的 LIKE 兜底覆盖。
```

| 设计 | 实现 |
|---|---|
| 中文分词 | `tokenize='trigram'`（建表失败自动降级 `unicode61`） |
| 查询安全 | `ftsQuote()` 把查询**短语化**并转义引号，避免 `MATCH` 语法错误 |
| 索引自愈 | 启动时比对 `memory_fts` 与 `memories` 行数，**索引少了就整体重建** |
| 1-2 字盲区 | FTS 之外叠加 `LIKE` 兜底路径 |

> **主动把已知盲区写进代码注释**，是这份代码里最"工程"的细节之一。

### 4.2 三级可见性 ACL（`memories.js:65-91`）

```
visibility = private | team | restricted（+ allow_members 白名单）
可见 = author 是我  OR  visibility=team  OR  （restricted 且我在白名单）
```

记忆分四类：`decision | preference | fact | conclusion`。

### 4.3 融合闭环的沉淀入口（`tasks.js:328-345` → `memories.js`）

任务完成 → `precipitateTaskMemory()` 自动写一条记忆，并带上：**任务来源（`source_task_id` / `source_agent`）、产物文件名、可见性继承**。

**一个防御性细节**：`visibility=restricted` 但**没指定任何成员**时，**降级为 `private`** 并留 `note` 说明——避免"限制可见但没指定谁能看"导致记忆事实不可见。

## 六、懒启动 `lazystart.js`（110 行）

| 环节 | 实现 |
|---|---|
| 探活 | `probe(port)` → `GET http://127.0.0.1:<port>/health`，带 `AbortController` 超时 |
| 拉起 | `ensureRunning(id)` → `hermes -p <id> gateway start` → **轮询 `/health` 上限 60s** |
| **并发合并** | 用 `inst.starting` Promise 复用——同一 Agent 的并发请求只拉起一次，其余等同一个 Promise |
| 空闲停机 | `sweep()` **每 5 分钟**一轮；**自建 Agent 空闲 >30min 停止**；4 个预设 Agent 常驻 |

| 失败处理 | 60s 未就绪**显式抛错**（`'Agent 启动失败，请管理员检查（60s 内 /health 未就绪）'`）——**不静默重试** |

> 关键设计：**就绪判定以"是否真正持有 API 端口"为准**，而不是"命令是否执行成功"。这与 §八 的就绪闸门是同一思路。

## 七、用量记账 `usage.js`（82 行）—— 全项目唯一落账点

文件头注释直接说明了**为什么需要它**：

> `/api/chat`、看板指令、@Agent 拉入、任务执行——四条路径每次都会真的调用一次上游 LLM，但在 C2 之前没有任何账目，负责人无法回答"本周花了多少、花在谁/哪个 Agent 身上"。

| 设计 | 实现 |
|---|---|
| 记账三元组 | `promptTokens` / `completionTokens` / `cacheReadTokens` |
| 计价 | 美元为基准，另存人民币展示值；单价常量集中在 `config.js`（价目变动只改一处，或环境变量覆盖） |
| 上游未回 usage 时 | **按字符数估算**，且 **CJK 与 ASCII 用不同经验系数**；结果标 **`estimated=1`** 以便与实测值区分 |
| DeepSeek 特性 | 用 `prompt_cache_hit_tokens` 表示缓存命中的输入（单价低两个数量级） |

**一条明确的铁律**（代码注释原文）：

> 记账失败绝不影响业务——所有出口 try/catch，只写 stderr，不抛给调用方。

> **可观测性不能反噬业务**，且**区分实测值 / 估算值**——这两点比"我们做了成本统计"重要得多。

## 八、进程与静态服务 `index.js`（99 行）

### 8.1 C-1 事故：Express 5 的 `app.listen` 会同时注册 error 监听

代码注释记录得非常完整（`index.js:57-65`）：

> express 5 的 app.listen 会把回调同时注册为 error 监听（`express/lib/application.js: server.once('error', done)`），端口被占用时回调照样被调用、入参是错误对象。**因此必须在回调内判断 err，否则第二实例仍会执行恢复/巡检（实测 EADDRINUSE 下回调被触发）。**

**修法**：回调内判 `err` → 提前 return；把**任务恢复、周期巡检、懒启动实例表初始化、空闲清扫**全部收进"**确认本进程真正持有 API 端口**"之后的 `startTaskRuntime()`。

注释还标注了这是"**第二版**"——第一版修得不彻底（只挪了恢复，没挪懒启动初始化，实测第二实例仍会写共享实例表、执行停服清扫）。

> 这是全项目**最典型的一次"只有真跑才会发现"的坑**：框架版本的一个行为差异，会让"双实例"从"启动失败"变成"**静默双写数据**"。

### 8.2 SPA 回退收窄（`index.js:70-90`）

原实现把所有未命中路径一律回 `index.html`，注释写明了两个后果：

| 后果 | 说明 |
|---|---|
| ① 缺失的静态资源返回 HTML | 浏览器按 JS 解析后报 `Unexpected token '<'`——**把"文件缺失"伪装成"代码报错"，极难定位** |
| ② `/api/xxx` 也返回首页 HTML | **掩盖后端路由错误** |

**现规则**：`/api` 前缀 → 404 JSON；带扩展名（视为静态资源）→ 404 纯文本；其余（前端路由）→ `index.html`。

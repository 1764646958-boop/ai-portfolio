# 03 · 开发过程与 AI 协作工程化

> 这一部分是本作品**最想展示的东西**：不是"我用 AI 写了代码"，而是"我建立了一套让 AI 产出**可验收、可回溯、可交接**的工程方法"。

## 一、方法骨架

```
① 唯一权威规格（含 36 条决策清单）
        │  规格即合同：与执行稿冲突时以规格为准
        ▼
② 把规格拆成「可独立执行、可独立验收」的批次（S0→S1→S2→S3，后接 S3.1/S4.0/S4.1）
        │  每批带：锚点、要求、验收方式、留档位置、禁区
        ▼
③ AI 编码代理执行（本机 + SSH 远程操作服务器）
        │  逐项自测，禁止静默跳过；改前备份 / 留 diff
        ▼
④ 报告即交接：产出写到服务器 reports/，下批先读上批报告再开工
        │  → 换工具、换人、断线重来都能无缝接上（不依赖聊天记录）
        ▼
⑤ 人做独立复核：不上自述、直接实测；关键项亲手重现
```

**为什么这么做**：AI 代理的产出"看起来对"和"真的对"差很远。把**验收权留在人手里**、把**证据留在服务器上**，是这套方法能跑通的两个支点。

## 二、给 AI 的每一份任务书都长这样（模板）

1. **位置与权威**：项目根、规格文件、当前基线报告（"先读它再动手"）；
2. **锚点**：文件 + 行号 + 现状代码片段（防止 AI 自行选点）；
3. **要求**：最小改动 / 加法优先 / 不重写既有模块 / 不扩散范围；
4. **禁区**：不重跑 `gateway install`、不卸载关键组件、保持既有 `UMask` drop-in、密钥只进 `.env` 且**不回显**；
5. **验收**：逐条可执行（命令 + 期望输出），必须附**原始输出**；
6. **回归**：每批跑一次端到端脚本（42 断言）；
7. **留档**：报告章节（问题 / 改动 / diff 摘要 / 验证证据 / 剩余风险）+ 双端 scp；
8. **失败处理**："先诊断再继续，禁止静默跳过"、"**禁止用『已知问题』蒙混任何验收项**"；
9. **未完成时**：按批交付并显式标注"未完成批次"，**不要半成品落地**。

> 效果：AI 的每一批交付都自带证据链，复核时只需抽查关键项，而不是重读全部代码。

## 三、工具通道的工程化切换（真实发生过两次）

| 情况 | 处理 |
|---|---|
| 首选通道触发用量限额（5 小时窗口） | 检查其**未写入任何项目文件**（零清理交接）→ 切到备用通道（另一款编码代理，本机运行 + SSH 远程）→ 交付不受影响 |
| 备用通道的模型档位报错（订阅档位不含超长上下文版本） | 定位到"启动时默认模型被重置"→ 在**启动命令里显式指定档位**（不依赖配置文件默认值）+ 全量文档口径统一（9 份执行稿） |
| 远程隧道掉线导致本地打不开工作台 | 诊断出"服务器正常、隧道进程消失"→ 改为**断线自动重连循环** + 提供一键重连脚本 |
| 期间服务器侧余额见底导致定时作业静默失败 | 复核时发现 → 催生**运维看门狗**（15 分钟体检 + 站外邮件告警） |

## 四、踩坑清单（都是"只有真跑才会遇到"的）

| # | 现象 | 根因 | 修法 |
|---|---|---|---|
| 1 | 第二实例启动瞬间把所有在途任务误判孤儿重排 | **Express 5 的 `app.listen` 会把回调同时注册为 error 监听** —— 端口占用时回调照常执行 | 回调内 `err` 感知 + 把任务恢复/巡检收进"确认持有端口"就绪闸门 |
| 2 | 清空记忆后，搜索仍能搜出已删内容 | **FTS5 外部内容表不随主表级联删除** | 按应用惯用法显式清空 FTS + **探针验证**（搜 4 个旧词应全 0） |
| 3 | 删除 Agent 后 systemd 目录仍有残留 | `gateway uninstall` 不清理创建时写入的 drop-in | 在删除接口里显式 `rmSync` drop-in 目录 + 复测 1→0 |
| 4 | 定时作业连续失败却无人知晓 | 作业 `deliver=local`，失败只在数据库里 | 独立于应用的看门狗（systemd timer）→ 通知 + 站外邮件 |
| 5 | 端口分配可能给到"已被别的进程占用"的端口 | 只查登记表、不做真实占用探测 | 解析 `/proc/net/tcp{,6}` 的 LISTEN 行，分配时排除"已登记 ∪ 正在监听" |
| 6 | 私聊/群聊里成员互发消息烧 token | 设计缺失 | 明确"**成员-成员不调 LLM**"（零成本）+ 用数据验证（不产生用量记录） |
| 7 | 登录后 JWT 可被 JS 读取、退出后旧 Cookie 仍可用 | 响应体回传 token / 无状态 JWT 不吊销 | 响应体去 token + `token_version`：登出即全端失效 |
| 8 | 2C4G 小机崩溃重启风暴会吃满 CPU | `Restart=always` + 启动限速为 0 | 限速 300s/10 次 + 触发限流由看门狗告警 |
| 9 | 改完前端却发现"改了个寂寞" | 生产路径不经过开发端口 | 两条路径都改 + 用**生产路径**复测三条 URL |
| 10 | 清理数据后，画像页仍在讲"旧世界" | 画像读的是历史快照文件，删数据≠删叙述 | 旧快照隔离（mv 非 rm）→ 按例行计划重跑重建；同时把"作业产物是否被读到"纳入验收 |

## 五、可复用的沉淀

- **规格治理**：规格换版时把"实现与文字不一致"的偏差**写实**并追认加法接口，而不是让文档与系统长期分叉；
- **批次模板**（上文 §二）可直接复用到下一个 AI 协作项目；
- **复核纪律**：不上自述、直接实测、关键项亲手重现、核验脚本只输出结论不回显密钥；
- **成本治理套路**：把"每日 AI 值班"降级为"**每日 0-token 脚本快照 + 每周 1 次 AI 周报 + 按需手动触发**"，成本降 93% 而信息量不降。

## 六、这套方法证明了什么

1. 小团队（甚至单人）**可以**用 AI 代理交付一个真实可运行的多人协作系统 —— 前提是把规格、验收权和证据链工程化；
2. **成本是可管理的**：先做用量可见，再按"该 AI 的 / 该脚本的 / 该按需的"三类重新分配；
3. **交付物是可信的**：每批自带 diff、原始输出与复核记录，任何人接手都能复现结论 —— 这正是 FDE / AI PM 岗位最需要的"把 AI 项目做成可验收工程"的能力。

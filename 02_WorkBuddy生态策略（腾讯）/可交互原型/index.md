# WorkBuddy · Agent 质量与分发原型（P3）

> 可交互原型：演示「一次**长尾需求**被**非头部资产**命中」的完整匹配链路。

## 如何运行

**零安装、双击即跑**：

- 直接打开 `index.html`（推荐 Chrome / Edge，其余现代浏览器亦可）。无需服务器、无需依赖、无需联网。

或本地起个服务（可选）：

```bash
cd prototype
python -m http.server 8000
# 浏览器打开 http://localhost:8000
```

## 演示效果（已验证）

以预设长尾需求「今晚要做清蒸鲈鱼，配什么清酒比较合适？」为例：

| 排序口径 | 第一名 | 命中 |
|---|---|---|
| **传统**（按调用量/评分） | MeetingSummarizer（51200 次调用） | 与"清酒配餐"几乎零契合 |
| **本框架**（语境×质量×生态） | **SakePairingAdvisor**（仅 84 次调用） | 语境适配 100%，最终分 91.1 |

左列展示"会被头部虹吸"的旧排序，右列展示本框架如何把**达标长尾**托举上来——这就是反马太的直观证据。

再如反马的**更硬核对照**（预设：「翻译这份 30 页的技术白皮书为英文」）：

| 排序口径 | 第一名 | 命中 |
|---|---|---|
| **传统**（按调用量） | MeetingSummarizer（51200 次调用） | 与"文档翻译"几乎零契合 |
| **本框架** | **HighQualityTranslator**（仅 95 次调用） | 语境适配 97%（与头部平移） |

关键不在"赢在语义契合"，而是：在与头部**完全同维、语义持平**（均约 97%）的条件下，本框架仍凭「基础质量 + 生态增益」选择更优质的达标长尾——证明结果由框架自身的两个差异化信号决定，而非仅靠语义搜索。当头部在语义与质量上确实是最优解时（如"会议纪要"），框架也照推头部——"反马太"是给长尾起跑线，不是为反而反。

## 结构说明（实验链路 = 10 阶段）

`需求理解 → 画像 → 召回 → 语境适配 → 质量接入 → 探索/利用 → 门禁裁决 → 分发 → 反馈 → 回流`

每个阶段均标注承担者（规则 / 模型 / 人），对应 P2《用户需求→Agent 分发链路设计》。

## 语义层说明（重要）

本原型为**本地轻量演示**，语义层用「能力维度 + 关键词映射」**近似模拟** LLM 的判断，以保证零配置、可复现、可离线跑。它不是真实大模型，但完整表达了评价框架的**体系与公式**：

- **语境适配度** = 需求向量 × 资产能力向量 的余弦相似度
- **基础质量** = 贝叶斯收缩（内容先验 + 行为验证，按证据量 N 加权），收缩平衡 k=5
- **生态增益** = 1 + α·(稀缺度 × 需求缺口)，α=0.15（膝点 0.2）封顶
- **探索/利用** 乐观值 = Q̂ + β·√(ln t / N)，β=0.15
- **最终分发分** = 语境适配度 × 基础质量 × 生态增益

### 如何替换为真实大模型

前端默认「离线近似语义」（零配置、双击即跑）。若要接真实 LLM：

1. 复制 `.env.example` 为 `.env`，填写你的 `LLM_API_KEY / LLM_BASE_URL / LLM_MODEL`。（key 只存服务端，不进前端 HTML。）
2. 运行本地后端：`python server.py`（默认 `http://127.0.0.1:8001`）。
3. 打开 `http://127.0.0.1:8001/index.html`，在「语义层」选择 **真实 LLM**，再点运行。

后端用 **OpenAI Chat Completions 兼容协议**（OpenAI / DeepSeek / Qwen(DashScope) / Moonshot(Kimi) / Zhipu(GLM) 等多数中文大模型均兼容）。它会调 LLM 做两件事：把需求映射到能力维度 + 对每个候选资产打分「语境适配度」，然后复用前端同一套质量/生态/门禁公式，仅语义层替换为真实模型。若后端未启动或 key 无效，前端自动回退到离线近似。

> 语义层来源会在界面的「语境适配度」旁标注：`（真实 LLM 打分）` 或 `（维度余弦近似）`。

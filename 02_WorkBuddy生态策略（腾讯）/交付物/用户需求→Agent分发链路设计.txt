Normal	用户需求 → Agent 分发链路设计
Normal	——WorkBuddy 开放 Agent 生态 · 从自然语言到资产命中的完整管道——
Normal	让每个阶段由最合适的判断者承担：模型、规则、人，各司其职
Normal	摘要
Normal	本设计把“用户用自然语言描述需求 → 命中合适的 Agent”拆成一条可审计的完整链路，并给出**每个阶段由规则、模型还是人来承担判断**及其原因。
Normal	核心采用一条**分工第一性原理**：凡是需要**开放语义推理、依赖世界知识与语境细腻度**的判断交给**模型**；凡是**可枚举阈值 / 公式、要求稳定可审计、要扛量且防作弊**的判定交给**规则**；凡是**不可逆、可申诉、涉及公平与权力**的裁决留给**人工**。
Normal	链路共 10 个阶段，覆盖从需求理解、候选召回、语境适配计算、质量排序、探索 / 利用决策、门禁生命周期裁定、分发执行、到反馈闭环与数据回流。它**消费 P1 的质量分、语境适配度、生态因子、门禁状态**，并内置“三次未命中即放弃”的兜底路径。
Normal	链路核心命题：在“合格基础上的最匹配优先”前提下，用探索/利用机制把长尾需求相机地交给达标长尾资产——这正是反马太策略的工程载体。
Normal	一、设计原则
Normal	1.1 判断分工的第一性原理
Normal	1.2 三个硬性约束
Normal	• 权力不自动：自动判定可加速，但“清退 / 争议”这类不可逆或涉及创作者权益的决定，必须留人，且可追溯、可申诉。
Normal	• 可审计：每次分发都应能回溯到证据子集（哪些信号、哪些数据），支撑“可采信”与创作者申诉。
Normal	• 可降级：链路在大模型不可用时仍有兜底（规则降级、关键词路径回归），避免单点依赖。
Normal	二、链路总览
Normal	整条链路按“输入 → 理解 → 召回 → 匹配 → 排序 → 探索 → 门禁 → 分发 → 反馈 → 回流”线性推进，其中探索与门禁形成对“长尾”的两道保护。
Normal	三、逐阶段细说明（判断分工与理由）
Normal	3.1 阶段① 需求理解
Normal	**承担者：模型为主 + 规则辅助**。模型解析自然语言为结构化需求（意图、实体、约束、质量预期）；规则负责实体参数硬抽取、格式校验与降级兜底（模型不可用时的关键词回退 / 预设槽位）。
Normal	为什么：理解“帮我总结这段会议纪要”这类开放需求是语义推理，规则无法枚举；但“时间、对象、输出形式”这类硬参数交由规则能保证稳定与可审计。模型管“懂”，规则管“准”与“稳”。
Normal	• 与 P1 衔接：输出同时接入 P1 的“需求理解层结果”，供后续簇识别与画像复用。
Normal	3.2 阶段② 需求画像 / 语境向量化
Normal	**承担者：模型 + 规则**。模型做语义嵌入与需求簇聚类（判断这是 head 常见需求还是长尾稀缺需求）；规则设定域标记、紧急度、配额的阈值（如“涉敏”“合规”“需人工复核”的域标记由规则枚举）。
Normal	为什么：簇的“归属”是语义量，需要模型；但“是否触达某种边界条件”应由规则显式声明，避免模型自行发挥触发不可控逻辑。
Normal	3.3 阶段③ 候选召回
Normal	**承担者：规则 + 模型**。模型提供语义向量相似度检索；规则做硬性资格过滤（启用状态、黑名单、合规、最低内容自证分）。
Normal	为什么：召回要“广”，相似度靠模型；但“哪些资产根本不该出现”是边界约束，必须用规则把住，防模型把不合规 / 下架资产召回。
Normal	3.4 阶段④ 语境命中适配度计算
Normal	**承担者：模型为主 + 规则**。模型对“候选 × 当前需求”打分，评估语义匹配度、能力边界契合度；规则对其中可量化的部分（如任务类型是否匹配、专精 vs 广度）做确定性约束。
Normal	为什么：这是“长尾命中”的关键——模型能识别“某个窄切片资产恰好最擅长这个冷门需求”；规则只兜底明显错配（如需求要文本、资产只能出图）。
Normal	3.5 阶段⑤ 质量接入与复合排序
Normal	**承担者：规则**。最终分 = 语境适配度 × 基础质量 × 生态增益（P1 定义），直接做确定性乘法与排序。
Normal	为什么：组合与排序是确定性、可审计、要扛量、需防作弊的运算，交给规则保证可复现；模型在此只提供输入，不做自由裁量——防止排序被“解释”带偏。
Normal	3.6 阶段⑥ 探索 / 利用决策
Normal	**承担者：规则**。对低于置信度阈值或处于高长尾候选，施加 P1 的 UCB 乐观加成（score_路由 = Q̂ + β·√(ln t/N)），或路由到探索预算池；β 与探索预算为可调常数。
Normal	为什么：这是反马太的开关——探索多少、探索谁，必须**可调、可回退、可观测**，用规则显式控制远比交给模型黑箱裁量更安全、更易归因。
Normal	这也回填了“加分项（马太抑制）”：探索 / 利用决策就是它的工程载体，稀缺度因子在此作路由偏好信号二次复用。
Normal	3.7 阶段⑦ 门禁与生命周期裁定
Normal	**承担者：规则 + 模型；人处理高风险**。底线闸门（绝对下限）与竞争闸门（同簇相对排名）由规则自动判定；模型提供质量分与稀缺缺口判断；稀缺豁免、清退、争议复核**留人工**且可追溯可申诉。
Normal	为什么：自动判定扛量大、可审计；但“把创作者资产清出生态”是不可逆、涉公平的决定，必须有人兜底，弥补纯算法可能造成的个体误伤。
Normal	3.8 阶段⑧ 分发执行
Normal	**承担者：规则 + 模型**。规则返回 top-k 命中结果并投递到曝光 / 推荐位；模型按需生成命中说明 / 个性化推荐语，让“为什么推这个”对用户可解释。
Normal	为什么：投递是结果性操作，规则保证稳定；推荐语属于体验优化，模型承担，且其输出不影响分发决策本身。
Normal	3.9 阶段⑨ 反馈闭环（含 3 次未命中兜底）
Normal	**承担者：规则 + 模型**。规则计数命中 / 放弃，超过 3 次未命中即触发“关键词检索路径”回归；模型对放弃原因做语义归因（是匹配差、资产差、还是需求太怪）。
Normal	为什么：“3 次即放弃”是明确阈值，用规则；“为什么放弃”是模糊归因，用模型，回填到资产质量与需求侧洞察。
Normal	3.10 阶段⑩ 数据回流与质量更新
Normal	**承担者：规则（收缩）+ 模型**。新行为数据回流，规则执行 P1 的贝叶斯收缩（Q̂ = w(N)·Q_行为 + (1−w(N))·Q_内容先验）更新基础质量；模型对内容变更重新注述、校准内容维度。
Normal	为什么：权重更新与收缩是确定性运算，规则算最稳；内容维度若发生变更（创作者改描述），需模型重新评估，二者互补。
Normal	四、关键机制专题
Normal	4.1 反马太的工程落点
Normal	链路对长尾提供两道保护：阶段⑥ 探索 / 利用（给长尾“被试一次”的机会）+ 阶段⑦ 稀缺豁免（内容先验合格即条件放行）。二者共同保证“达标长尾有资格被看见”，而非被头部虹吸埋没。
Normal	4.2 “3 次未命中→放弃”的兜底设计
Normal	在阶段⑨设置“命中判断”：若用户采纳命中（继续对话 / 使用），视为命中；若连续 3 次匹配都未获采纳，则：① 回退到关键词检索路径；② 将本次需求标记为“未覆盖需求”，供需求洞察与创作者激励（“谁来做这个缺口”）。这既护住用户体验，又给生态提供了“供给缺口”信号。

Normal	六、结论
Normal	本设计把“自然语言需求 → 资产命中”组织为 10 阶段链路，用“模型 / 规则 / 人”的判断分工原则（语义归模型、确定性归规则、不可逆归人）逐一定义承担者与理由；通过探索 / 利用与稀缺豁免实现对长尾的保护，用“3 次未命中→回归关键词”兜底体验与供给缺口信号。它完整承接 P1 的质量基座，并为 P3 原型与 P4 指标提供工程骨架。

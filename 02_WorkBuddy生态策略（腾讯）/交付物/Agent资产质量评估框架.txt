Normal	Agent 资产质量评估框架
Normal	——WorkBuddy 开放 Agent 生态 · 平台侧生态治理基础设施——
Normal	用 AI 即时推断质量，打破冷启动死锁，让达标长尾有资格被看见
Normal	摘要
Normal	WorkBuddy 已从单 Agent 助手升级为开放 Agent 生态平台，用户以自然语言描述需求，即可获得最合适的 Agent。然而，当前平台的供给分发仍停留在“关键词检索 + 头部虹吸”：用户搜到的未必是当下最匹配的，需二次筛选后再放弃；新晋创作者的高质量资产因缺乏曝光而“有质无市”，平台整体呈明显马太效应——头部资产反复被分发，达标长尾难以触达用户。
Normal	本框架是 WorkBuddy 平台侧的“生态治理基础设施”，为“一份 Agent 资产是否值得继续被分发”给出可判定、可校准、可采信的标准。其核心命题是一句话：打破“无流量 → 不敢推 → 更无流量”的冷启动死锁。
Normal	为此，本框架采用“连续质量分为底座 + 派生门禁 + 诊断视图”的形态；以“语境命中适配度 × 资产基础质量”的双因子结构组织分发优先级；建立“内容可推断 + 行为已验证”的双轨评分体系，使零流量长尾可被内容维度托起、待数据积累后再由行为维度校准；并以“评分用收缩、路由用乐观、叠加探索预算”的冷启动三件套、“绝对下限 + 相对竞争 + 稀缺豁免”的三层门禁，实现长尾友好且不被刷分的生态治理；最终通过“金标准锚点、多源交叉验证、抗注入、行为真伪过滤、透明申诉与人工兜底”五支柱，回答“平台是否可采信本框架”。
Normal	框架定位钩子：用 AI 即时推断质量（而非等待历史流量），让达标长尾“有资格被看见”。
Normal	一、背景与问题定义
Normal	1.1 场景还原
Normal	用户侧：描述需求后，若三次匹配仍未命中即放弃，退回关键词检索路径——意味着自然语言交互红利归零。
Normal	创作者侧：仅 8% 的创作者在资产发布后两周内获得超过 100 次调用，多数活跃资产长期得不到分发。
Normal	平台侧：具备通用大模型、工作流编排，以及资产元数据（名称、描述、调用量、评分、token 消耗、失败率与退出原因分布）、对话日志、需求理解层结果、曝光位 / 推荐位 / 搜索排序接口、创作者后台与激励结算通道。
Normal	1.2 核心矛盾
Normal	用户需要的不是“被搜到”，而是“被命中”；平台需要的不只是“分发”，而是“让对的资产被对的人命中，同时让长尾有赢的可能”。
Normal	传统平台优化“检索效率”；本框架要解决的是“匹配质量 + 生态多样性”。
Normal	1.3 三个被数据暴露的病灶
Normal	• 意图 / 能力错位：用户描述的是意图，不是能力名；关键词检索把“翻译成本”转嫁给用户，要求用户先会搜索。
Normal	• 头部虹吸：搜到的 ≠ 最好的。任何基于历史行为的排序都会继续强化头部，构成马太效应的自洽闭环。
Normal	• 冷启动死锁：没数据 → 不敢推 → 更没数据；长尾即便能力达标也进入死循环。
Normal	二、产品定位
Normal	2.1 定位陈述
Normal	WorkBuddy 资产质量评估框架，是平台侧的“生态治理基础设施”——它不是用户直接感知的功能，而是平台用来做供给准入、质量校准、激励结算、生态调优的底层基座，把“让生态从头部虹吸转向优胜劣汰”这一平台战略，落成一套可被系统调用的连续质量分 + 派生门禁。
Normal	2.2 主用户与价值链
Normal	2.3 差异化价值（定位的钩子）
Normal	传统模式下，平台只能“等一个资产跑出数据”来判好坏，这正是长尾死锁的根源。本框架的差异化在于：以 AI 从资产内容与既有行为信号中“即时推断”质量，让评价不再依赖“它已经火了”，而依赖“它有没有资格被推一次”。
Normal	三、框架总体设计
Normal	3.1 形态：三层组合
Normal	3.2 双因子结构
Normal	分发优先级 = 语境命中适配度（contextual fit） × 资产基础质量（base quality）
Normal	语境适配度随需求变化，用于把“对某个冷门需求完美适配”的长尾顶到最前，即使其全局流量低；基础质量稳定、可解释、可跨资产比较，用于支撑“值得分发”的门禁与创作者的可改进性。两者相乘，天然形成“合格基础上的最匹配优先”。
Normal	3.3 打分对象与边界
Normal	本框架评估的对象是“资产”（Agent / Skill / Plugin / MCP），而非单次对话。它给出两个输出：① 资产基础质量分（0~1）；② 语境命中适配度（由匹配层计算，P2 落地）。本框架负责①，并为②提供语义对齐等输入。
Normal	四、质量分维度体系
Normal	4.1 双轨原则：内容可推断 + 行为已验证
Normal	平台元数据分两类：内容信号（名称、描述、能力自述，零流量亦可读）与行为信号（调用量、评分、失败率、token、退出原因，需跑出数据）。本框架把质量劈成“内容可推断”与“行为已验证”双轨：冷启动时靠内容维度托底，数据累积后由行为维度经贝叶斯校准接管。
Normal	4.2 核心维度（固定 6 维）
Normal	4.3 生态调节维度（新增，乘性封顶）
Normal	4.4 权重与冷启动 → 稳态切换
Normal	计算式：最终分 = 核心质量分(0~1) × 语境适配度 × 生态增益系数
生态增益系数 = 1 + α·(稀缺度 × 需求覆盖缺口)，α 取 0.1~0.2，并对该项封顶（如 +20%）
Normal	权重设计：“语义对齐 + 内容自证”在无数据阶段权重拉高（如冷启动时约 60%）；随着行为数据累积，“有效性 / 可靠性 / 满意度 / 成本效率”经贝叶斯收敛逐步接管，稳态时行为验证约占 70%。这样一套分数、两个阶段权重自动切换，无需两套公式。
Normal	• 防作弊关键：稀缺度永不替代质量：调节维度为乘性 + 封顶，只抬升“在合格之上的稀缺资产”，不会让基本功不行的资产靠“没人做”反超。
Normal	• 锚定真实需求：需求覆盖缺口兜底：光稀缺不够，得“稀且真有人需要”才加成分，堵住“故意做冷门但没人用”的刷分。
Normal	• 防拆分：防拆分刷稀缺：用语义聚类判是否重复能力，重复即合并、不给稀缺加成，并对“疑似拆分”作为异常上报人工。
Normal	• 专精优先：方向偏好专精：长尾需求往往是窄需求，且专精资产更适合被工作流编排组合；稀缺度因子在 P2 的 explore/exploit 中作路由偏好信号二次复用。
Normal	五、冷启动评分机制
Normal	冷启动是反马太的命门。根本难点在于循环死锁。解法关键是把“评分”与“路由”拆开：
Normal	5.1 探索预算（保证首次曝光）
Normal	仅靠公式不够——冷启动资产还需“确保性的第一次曝光”来产生 N。平台应为“内容先验合格但无行为数据”的资产，分配固定小额探索预算：譬如每个滚动窗口保留 X% 的路由位给探索池，或给每个合格新资产保底 K 次曝光。这与任务背景“曝光位、推荐位、搜索排序接口均已具备”直接衔接。
Normal	5.2 关键常数与取值思路
Normal	探索方向默认中等偏保守：它是冷启动引导而非长期策略，过量探索会在稳态时伤及“当下最匹配”的体验。
Normal	5.3 常数额外线校准：可复现 demo
Normal	三个常数 k / β / α 不拍脑袋硬给，而是用「离线历史日志（或带真值的合成数据）」回溯标定。方法与配套脚本见同目录 “p1_backtest.py”（纯标准库、seed=42 固定可复现）。以下为用合成日志跑出的示意结果，真实落地时替换为平台真实历史日志即可。
Normal	方法要点：① k 的标定说明「多早信任行为分」是数据问题，可用预测力定量回答；② β 是「探索收益 vs 成本」的权衡，离线重放可给出帕累托曲线；③ α 是乘性封顶的弱杠杆，校准重点是找到「多样性改善且质量不塌」的膝点，而非一味抬高——这与“稀缺度永不替代质量”的设计一致。
Normal	六、门禁与资产生命周期
Normal	6.1 为什么不是一条固定分数线
Normal	• 领域差异：跨领域不可比：翻译与代码生成的质量分分布不同，同一分数线做不到公平。
Normal	• 稀缺长尾：不兼容稀缺：稀缺且合格的长尾基础分未必顶尖，但生态价值极高，纯分数线会一刀切掉。
Normal	• 确定性目标：可被刷分：固定分数线给作弊者一个确定性目标（“只要堆到 60 就永远有曝光”）。
Normal	6.2 三层裁决
Normal	6.3 生命周期（而非一次性布尔）
Normal	准入（draft）→ 试用（explore，小额保底曝光）→ 常规（exploit，竞争通过后）→ 清退（失败 / 长期无命中）
Normal	“值得继续被分发”落地为一个持续的状态机问题，而不是“过一次就永远 / 完全不能发”的一刀切。这与“连续分为底座、门禁为派生”的形态互相印证。
Normal	6.4 最后一刀谁砍（职责分工）
Normal	底线闸门、竞争闸门的自动判定可由规则 + 模型承担（有明确阈值 / 排名）。但清退、争议、稀缺豁免复核这三类高风险裁决，必须留人工，且可追溯、可申诉。这不是保守，而是“平台能否采信”的最后一层信任：自动分给建议，但“把创作者资产清出生态”这种不可逆决定，须有兜底审核。
Normal	七、平台是否可采信：五支柱采信设计
Normal	本框架若被平台采信，须正面回答三个潜在质疑：它会不会被单源带飞？它会不会被作弊击穿？它是不是平台一面之词？五支柱逐一作答。
Normal	7.1 攻击面盘点
Normal	7.2 五个支柱
Normal	平台采信本框架，是基于它“有独立锚点、有交叉验证、有抗注入 / 抗刷分防线、有透明申诉与人工兜底”——评分不是自说自话，而是可核、有锚、能纠偏、有人管。
Normal	八、与生态其他环节的衔接
Normal	8.1 对外接口
Normal	• 评分接口：质量分（0~1）作为连续值，供分发链路、搜索排序、激励结算调用；与 P2 的语境适配度相乘得最终分发优先级。
Normal	• 诊断视图：基础质量 + 门禁状态 + 证据子集，写入创作者后台“诊断视图 C”，支撑“为什么没被分发 / 该改什么”。
Normal	• 因子复用：稀缺度 / 需求缺口因子，作为 P2 的 explore/exploit 路由偏好信号复用——一次评估，既做质量也做生态调优。
Normal	8.2 与任务要求的映射
Normal	九、落地实施建议
Normal	9.1 分阶段推进
Normal	• 阶段一（冷启动）：以内容维度（语义对齐 / 内容自证）+ 稀缺 / 缺口先行，启用“评分用收缩、路由用乐观”的冷启动机制，让无数据资产先被托起。
Normal	• 阶段二（补数据）：为合格新资产分配探索预算，接入曝光 / 排序接口；积累行为数据后，贝叶斯收敛逐步切换到以行为验证为主。
Normal	• 阶段三（可信闭环）：引入金标准评测集，定期校准分数；开通诊断视图与申诉，落地人工安全阀。
Normal	9.2 风险与缓解
Normal	十、结论
Normal	本框架以“连续质量分 + 派生门禁 + 诊断视图”为形态，用“语境适配度 × 基础质量”的双因子结构组织分发优先级；借“内容可推断 + 行为已验证”双轨评分，让零流量长尾可被内容托起、待数据后由行为校准；以“评分收缩 / 路由乐观 / 探索预算”打破冷启动死锁，以“绝对下限 + 相对竞争 + 稀缺豁免”三层门禁与生命周期实现长尾友好且不被刷分；最终以五支柱采信设计，正面回答“平台是否可采信”。
Normal	它独立支撑起平台对“一份资产是否值得继续被分发”的判断，并为 P2 分发链路、P3 原型、P4 指标提供一致的质量基座与输入。

α（生态增益） | 生态增益重算分发，看「多样性（Gini↓为佳）抬升」与「命中质量损失」形成的膝点；在质量不损前提下取 Gini 最低者 | α=0.2 Gini 0.444（最低、最均衡）/ 命中质量 0.754；α≥0.3 过度抬稀缺，多样性反弹变差 | α ≈ 0.2（多样性最佳且质量未损）

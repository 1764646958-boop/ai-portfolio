# 视野侵蚀 Shader 接入引擎 · 人工操作清单

> 交付物③ · 成员 A · 2026-08-25
> 目标：10 分钟内把视野侵蚀战斗效果在 MagicAI（Godot 4.6.2）里跑起来。
> 前置：MagicAI 项目已创建（或复用现有项目）。

## 一、文件放置（3 个文件，按此结构复制）

```
你的 Godot 项目/
├── assets/
│   └── shaders/
│       └── 视野侵蚀Shader原型.gdshader   ← 从 W1/shader/ 复制
├── scripts/
│   └── battle_test.gd                    ← 从 W2/shader/ 复制
└── scenes/
    └── battle_test.tscn                  ← 从 W2/shader/ 复制
```

> ⚠️ `battle_test.tscn` 里的路径引用就是上面这个结构（res://assets/shaders/… 和 res://scripts/…），
> 请严格按此放置；若项目结构不同，用文本编辑器打开 tscn 改两处 path 即可。

## 二、运行验证（5 步）

1. 打开 `scenes/battle_test.tscn`（若首次打开提示找不到脚本/材质，检查第一步的路径）
2. 按 F6（运行当前场景）
3. 预期看到：
   - **0-30s（阶段一）**：冷蓝遮罩从屏幕边缘向中心缓慢收缩，透明度渐增（控制台打印「进入阶段 1」）
   - **30-60s（阶段二）**：侵蚀继续加深，视野被压缩（控制台打印「进入阶段 2」）
   - **60-90s（阶段三）**：维持高压（打印「进入阶段 3」）
   - **90s 后**：遮罩缓缓退散（演示用后摇）
4. 按 Esc 或关闭窗口停止
5. 打开调试器 → Monitors → Frame Time：日常帧率应 ≥60fps（战斗遮罩是纯 alpha 叠层，开销近 0）

## 三、调参速查（Inspector 或 set_shader_parameter）

| 参数 | 默认 | 调整效果 |
|---|---|---|
| `erosion_progress` | -1（自动演示） | 战斗驱动时 0~1；-1 为预览循环 |
| `erosion_speed` | 0.15 | 自动演示速度 |
| `erosion_opacity` | 0.88 | 遮罩不透明度（越大越"实"） |
| `edge_softness` | 0.14 | 边缘柔化（0=锐利硬边） |
| `erosion_color` | 冷蓝 #0D214D | AI 界面压迫色（对齐美术 12 色卡「冷蓝」） |
| `erosion_center` | (0.5, 0.5) | 遮罩中心（可让 AI"眼睛"漂移） |

脚本内置外部接口：`reset_battle()` / `set_erosion_progress(p)` / `set_erosion_opacity(o)`（W3 战斗系统调用）。

## 四、分辨率口径（重要）

- **最终渲染分辨率统一 1920×1080**（集成决策冲突 5 已拍板）
- 美术方案 v3.1：场景图云端 4x-UltraSharp 放大 → **VRAM 压缩回 1920×1080 入库**（≤500KB）——放大是过程手段，不是最终尺寸
- ColorRect 用 anchors 铺满（已写好），任何分辨率自适应，无适配成本

## 五、性能基线（PerfDog 压测入口，W5 周六）

| 项 | 基线 |
|---|---|
| 日常场景 | 60fps（无后处理） |
| 战斗场景（本测试场景） | 30fps 硬底线，目标 60fps |
| 后处理 GPU 预算 | < 2ms/帧（当前纯遮罩 ≈0ms） |

## 六、常见问题

| 问题 | 原因/解法 |
|---|---|
| 画面全黑 | ColorRect 没铺满或 material 没挂上；检查 anchors 与 material 属性 |
| 没看到侵蚀动画 | shader 里 erosion_progress 默认 -1 自动演示（预览模式）；跑 battle_test.gd 才是战斗驱动 |
| 点击被遮罩挡住 | 检查 Overlay 的 mouse_filter=2（IGNORE，tscn 已设） |
| 控制台中文乱码 | 终端编码问题，不影响运行 |

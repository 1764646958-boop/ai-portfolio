### 1.2 边界与容错行为（均已实现并实跑验证）

| 输入 | 行为 |
|---|---|
| `t` 超出 [-10, +10] | `clampf` 到边界（t=-99 → 与 t=-10 同值） |
| `t` 为 NaN | `push_warning` + 按 0.0（MEDIUM 锚点）处理，不崩 |
| `battle_index` 非 1/2/3 | `push_warning` + 回退第 1 战值 |
| `tier` 缺省 `""` | 实时读 `TrustDrift.get_trust_tier()` |
| `tier` 大小写/别名 | 含 `HIGH` → HIGH；含 `MEDIUM`/`MID` → MEDIUM；含 `LOW` → LOW |
| `tier` 无法识别 | `push_warning` + 回退 `MEDIUM_TRUST` |
| `/root/TrustDrift` 不存在（或实例未入树） | `push_warning` + 回退 MEDIUM 锚点，**不报错、不阻断战斗流程** |

> 实现只调用 `TrustDrift` 的公开方法（`get_trust_score()` / `get_trust_tier()`），不触碰其内部变量；
> 依赖前先 `has_node()` 检查，缺失即回退——满足「不依赖 B/C 文件的内部实现」约束。

## 2. 与 B 终稿数值逐项对照

### 2.1 B2 二轨制公式（逐点实测）

| `trust_drift` | B2 终稿压力对 | 实现实测 | 判定 |
|---|---|---|---|
| -10 | (1.0, 0.0) | (1.0000, 0.0000) | ✅ OK |
| -5 | (0.75, 0.25) | (0.7500, 0.2500) | ✅ |
| 0 | (0.5, 0.5) | (0.5000, 0.5000) | ✅ |
| +5 | (0.25, 0.75) | (0.2500, 0.7500) | ✅ |
| +10 | (0.0, 1.0) | (0.0000, 1.0000) | ✅ OK |
| -99 / +99 | 应 clamp 到 ±10 | (1.0000, 0.0000) / (0.0000, 1.0000) | ✅ |

- 语义落地：`dialogue` 轨值越高 = AI 话术压迫越用力（trust 低时）；`qte` 轨值越高 = AI 越接管操作（trust 高时）。
- **`dialogue` 轨不驱动 warmth**：按 B2 表「trust 越高，warmth↑」——warmth 恒高（0.85~0.95 由对话引擎保证），
  二轨只驱动「压迫感 / 接管度」。接入时请勿把 `dialogue_pressure` 直接乘到 warm­th 上（会反向）。
- **两轨不做窗口插值**：`qte_pressure` 是连续压迫量，B1 窗口是**离散阶梯**；B 未给「压力→秒数」的插值规则，
  故本补丁**并列提供**两者，不用 `qte_pressure` 反算窗口。若 B 想要连续插值（如 `4.0 - 3.0 * qte_pressure` 之类），
  需要先拍板公式。

### 2.2 B1 反应窗阶梯（9 格逐格实测）

| 第 2 战（拉锯期） | 2.5 ✅ | 2.0 ✅ | 1.5 ✅ |

## 4. ⚠️ 待 B 复核清单

### 4.1 【必复核】`score ↔ trust_drift` 换算常量（A 建议值）

`trust_drift_collector` 的 `score` 是**0 起累积、只增不减**（无负值），而 B2 的压力公式需要 -10~+10 的 `trust_drift`。
两套值域并存，本补丁按 **tier 取代表锚点**换算。取值依据 B 的两张表（不是我拍脑袋）：

| tier | B 的 tier↔drift 区间<br>（battle_difficulty_curve.md 末表） | B 的「该战进入区间」<br>（battle_narrative_rhythm.md 总览表） | mapper 取值 | 取点说明 |
|---|---|---|---|---|
| `LOW_TRUST` | -10 ~ -3 | 第 1 战：偏向不信任 **-6 ~ -3** | **-5.0** | 落在第 1 战入口区间内，取**偏保守侧** |
| `MEDIUM_TRUST` | -2 ~ +2 | 第 2 战：中性 **-2 ~ +2** | **0.0** | = 区间**中点** |
| `HIGH_TRUST` | +3 ~ +10 | 第 3 战：偏向信任(+3~+6) → 极度信任(**+7**~+10) | **+7.0** | = 第 3 战**触发门限**（battle_narrative_rhythm §第 3 战触发表「trust_drift ≥ +7」；B7 亦以 +7 为界） |

**一句话规则**：锚点 = 该档对应战斗的**入口信任值**。

**备选值（若 B 想换口径，改 3 个常量即可）**：
- 取「tier 区间中点」：LOW → **-6.5**（区间 -10~-3 中点）/ MEDIUM → 0.0（不变）/ HIGH → **+6.5**（区间 +3~+10 中点）
- 取「该战入口区间中点」：LOW → **-4.5**（-6~-3 中点）/ MEDIUM → 0.0 / HIGH → **+8.5**（+7~+10 中点）

**若 B 改走 drift 制**（collector 直接累积 -10~+10）：本函数可整体替换为「直接返回 `get_trust_score()`」，
三个锚点常量与两张表均不受影响——这也是把换算集中在 `trust_drift_from_collector()` 一个函数里的原因。

### 4.3 【必复核】tier 读取时机：战斗开始快照 vs 实时

当前实现：`tier` 参数**缺省时实时读**（每次调用都会取最新 tier）。

推荐接入方式：**战斗开始时快照一次**，战斗内（同一场次）不再变档——

```gdscript
var _battle_tier := TrustDrift.get_trust_tier()   # _ready() 或战斗开场时
var win := TrustPressure.battle_qte_window(_battle_index, _battle_tier)
```

理由：B1 的窗口是「一场战斗一档」的**阶梯**，若战斗中 tier 恰好跨过 3 / 7 阈值，实时读会让同一场战斗的
反应窗中途跳变（玩家可感知的难度抖动）；而 `battle_difficulty_curve.md` 的语义是「第 N 战按当时 tier 取一格」。
**请 B 拍板**：若确实想要「信任升高即时压缩反应窗」的动态压迫（B2 的「接管」语义也可能支持这种做法），
则保留实时读，并在该战开始时只做一次快照用于音频/视觉的档位一致性。

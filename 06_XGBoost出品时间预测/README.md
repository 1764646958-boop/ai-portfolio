## 一句话

用门店历史订单预测**一单饮品要做多久**（出品时间），把"凭经验估"变成"可解释的分钟数"，
并用**保守偏移**让预测在排班/承诺场景下可用 —— 宁可高估一点，也不让顾客等超时。

## 训练流水线（`src/xgboost_prediction.py`，7 步）

```
[1/7] 数据加载
[2/7] 数据清洗
[3/7] 特征工程
[4/7] 数据划分（普通单按时序 / 预订单全量）
[5/7] 模型训练
[6/7] 综合评估（含 6.2 误差分布）
[7/7] TimeSeriesSplit 交叉验证（普通单）
```

### 特征工程（第 3 步，五块）

| 块 | 内容 |
|---|---|
| 3.1 **时间特征** | 从点单完成时间拆出 **11 个特征**（含时段分段 `get_period`） |
| 3.2 **杯数特征** | 单量与品类相关特征 |
| 3.3 **订单类型特征** | 堂食 / 外带 / 小程序等 |
| 3.4 **门店特征** | 门店维度编码与目标编码 |
| 3.5 **构造特征：并发与负载** | 并发单量、负载压力，**含交互特征** |

### 为什么要「按时序划分」而不是随机划分

普通单必须**按时间切分**训练/测试集 —— 随机划分会让模型"看到未来"，指标虚高。
预订单因为下单与出品存在提前量，单独处理（全量）。

### 误差分析与保守偏移

- `[6/7]` 阶段输出 **6.2 误差分布**：按订单类型、按时段分组统计 MAE，并打印 **Train / Test MAE 与 Gap**，用于判断过拟合。
- 推理侧 `run_predict(...)` 带 **`conservative_offset`** 参数（默认 0.5 分钟）：
  在预测值上做**保守偏移**，让承诺时间偏向"宁可多给一点"，降低超时风险。
  具体取值依据见 `项目报告.docx` 的「保守偏移设计说明」。


## ⚠️ 数据说明（重要）

- **`prediction_tool/test_sample.csv` 是合成数据，不是真实订单。**
  为保证可演示性，保留了原文件的表结构、列名与行数规模，但：
  **顾客手机号统一替换为 `10000000001`–`10000000703`**（11 位、唯一、不匹配任何手机号规则），
  订单号 / 门店 / 时间戳等也一并合成。
- **客户真实数据不随本仓库分发**，备份保存在本地 `prediction_tool/_真实数据（勿发布）/` 并已被 `.gitignore` 锁定。
- 因此：本仓库里的模型文件是**基于客户数据训练的历史产物**，`test_sample.csv` 仅用于演示"工具能跑"，两者不对应同一批样本。
- 复现训练需要自备同结构数据；**列名与特征构造见 `src/xgboost_prediction.py` 第 3 步**。

## 边界

- 指标口径：MAE（分钟）、R²、按类型/时段分组的误差分布。
- 这是**离线建模与离线评估**，未做线上 A/B；文中的业务收益推算是估算，不是实测。
